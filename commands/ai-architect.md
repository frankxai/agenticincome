# /ai-architect — Income Architecture

Requires `income/00-capability-inventory.md` (if missing, run `/ai-assess` first). Read it, plus `knowledge/02-income-models.md` for the model economics. Input: `$ARGUMENTS`.

## Process

1. **Model selection.** Apply the honest selector from knowledge/02 to their inventory: cash horizon + existing surfaces + capacity → entry model (service / product / system). State the choice and the *because*.
2. **The one thing.** Within the model, pick ONE concrete play built on their strongest leverage candidate. Name it plainly ("AI workflow implementation for boutique law firms", "The <niche> Template Vault", "A weekly <topic> publication with an affiliate registry").
3. **Business plan (write it fully, but scenario-honest):**
   - Who it serves + the searing problem (their words, not marketing words)
   - The mechanism (what gets delivered/sold, how agents fulfill it — cite the fulfillment pattern from knowledge/03)
   - Unit economics in **ranges with assumptions** (price band, cost per delivery incl. agent spend, capacity ceiling) — label every number "scenario, not forecast"
   - Distribution: which existing surface carries it + one new earned channel max
   - Stack: the five slots from knowledge/04, chosen for THEM
   - Risks + kill criteria (borrowed from /dpi doctrine: what result by what date, or stop)
4. **90-day map.** Weeks 1–2 build, weeks 3–4 first revenue attempt, months 2–3 packaging/compounding — following the path in knowledge/02, adapted to their hours/week.

## Artifact

Write `income/01-income-architecture.md` with all of the above, ending with:
- **This week's three moves** (concrete, ≤1 day each)
- Provenance line + "Next: `/ai offer` to spec the sellable thing."

Doctrine: ONE play (refuse portfolio-building at this stage — that's /dpi's job later); ranges not promises; the kill criterion is mandatory — an architecture without a kill date is a wish.
