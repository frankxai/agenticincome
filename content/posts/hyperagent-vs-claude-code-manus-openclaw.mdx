## 1. Working memory and compaction survival

Every long-running agent task eventually hits the context window ceiling. When an agent compacts its conversation history, unstructured chat logs lose file paths, rejected approaches, and edge-case constraints. The four platforms solve compaction survival through fundamentally different mechanisms:

- **Hyperagent (`Thread Context` 9-section working memory):** Instead of relying on an unstructured summary when a thread compacts, Hyperagent maintains an explicit 9-section `Thread Context` document inside the workspace (`Goal`, `Current State`, `Key Decisions`, `Constraints`, `Active Files & Artifacts`, `Open Questions`, `Completed Steps`, `Next Steps`, and `References`). Because each section has a dedicated slot, compaction updates the structured state rather than overwriting constraints with recent tool output.
- **Claude Code (`CLAUDE.md` + `AGENTS.md` + local filesystem):** State durability is anchored in the git repository itself. Instructions live in checked-in `CLAUDE.md` and `AGENTS.md` files, and task state survives across sessions only when written to disk (such as plan files, test suites, or git commits). If a constraint stays only in the chat transcript, auto-compaction can compress it away.
- **OpenClaw (`SOUL.md` + `MEMORY.md`):** Designed for continuous personal assistant continuity rather than single-project codebases. Identity invariants live in `SOUL.md`, while long-term user preferences and episodic notes append to `MEMORY.md`. This works well for cross-week messaging continuity, but lacks per-task artifact indexing unless paired with a structured project folder.
- **Manus (session-scoped scratchpad):** Maintains an internal task todo list during a cloud run, but provides limited schema control over what survives across separate threads once a task closes.

## 2. Artifact delivery and preview surfaces

How a buyer or reviewer inspects the output determines how fast you can verify quality before handoff.

- **Hyperagent (tri-modal split canvas):** Combines three delivery primitives in a side-by-side workspace: `CreateDocument` for structured markdown reports, `PublishWebpage` for rendering a live interactive iframe preview directly beside the thread, and downloadable `.zip` source bundles. For scoping briefs, interactive calculators, or client-facing prototypes, reviewers can inspect the rendered webpage immediately without cloning a repository.
- **Claude Code (git worktrees + local toolchain):** Operates directly on local filesystems and isolated git worktrees. It does not host an iframe canvas of its own; instead, it commits code that triggers your existing CI pipeline and deployment previews (such as Vercel Git integration). For production applications, repository-native delivery remains the gold standard.
- **Manus and OpenClaw:** Manus outputs downloadable files and hosted sandbox previews for single runs, while OpenClaw delivers text responses, diffs, or file attachments back through its configured messaging or terminal channel.

## 3. Trajectory learning and inline distillation

When you correct an agent mid-task—for example, instructing it to use sentence-case headings or to fail closed on missing configuration—most runtimes forget that correction in the next session unless you manually edit a configuration file.

- **Hyperagent (`Suggested learnings` inline distillation):** When a trajectory surfaces a reusable preference or correction, Hyperagent emits an inline `Suggested learnings` card inside the thread. A human operator reviews and approves the distilled rule with one click, promoting it into durable agent memory without hand-editing markdown files.
- **Claude Code and OpenClaw (explicit file commits):** Learning is manual or skill-driven. In Claude Code, you must explicitly write the lesson into `CLAUDE.md` or a repository rule file and commit it to git. That extra friction prevents accidental memory pollution—every rule has a git blame—at the cost of requiring deliberate end-of-session hygiene.

## 4. Migration paths and MCP interoperability

Lock-in happens when an agent platform traps your prompts, memory files, and tool definitions inside a proprietary UI.

- **Import from OpenClaw and Manus:** Hyperagent includes dedicated migration wizards (`Import from OpenClaw` and `Import from Manus`) that ingest existing `SOUL.md` / `MEMORY.md` bundles or task archives and map them into Hyperagent's structured workspace format.
- **MCP server exposure with `executionMode: confirm`:** Beyond consuming external Model Context Protocol (MCP) tools, Hyperagent exposes its own threads and agents as an MCP server (`list_agents`, `create_thread`, `send_message`, `get_thread`, `list_pending_approvals`, `resolve_approval`). Crucially, mutating or external actions support `executionMode: confirm`, pausing execution in a pending-approval state until a human resolves the gate. This aligns directly with the human-gate requirements enforced in the [Income Graph workbench](/workbench).

To translate abstract credit balances into real work, map your expected monthly usage across three outcome-anchored complexity bands (now codified in `lib/income-graph/economics.ts`):

1. **Quick task ($1–$5 credit band, $3 midpoint):** Research a topic, draft an email, summarize a document, or generate an image.
2. **Deep work ($5–$45 credit band, $25 midpoint):** Produce a full competitor report, build a landing page on the split canvas, run a multi-step data pipeline, or create a video asset.
3. **Run your business ($50–$200+/day credit band, $125/day midpoint):** Always-on agents handling operations, marketing preparation, outreach staging, monitoring, and recurring workflows.

### The CFO rule on credit ladders vs. BYOK

A progressive credit bonus (up to +45% at the $10,000/mo tier, reducing effective credit cost to ~$0.69 on the dollar) only saves money **if your monthly utilization consistently consumes the committed balance**. If your workload is spiky—such as running two deep-work sprints one month and none the next—unspent monthly credits expire or sit idle, erasing the nominal bonus percentage.

For variable workloads or strict cost-floor control, routing BYOK API keys through **Vercel AI Gateway** (or running Claude Code against direct provider billing) ensures you pay strictly for tokens consumed, with zero commitment breakage.
