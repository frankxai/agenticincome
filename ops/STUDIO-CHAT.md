# Revenue conversation runtime

`POST /api/studio/chat` accepts same-origin JSON with up to eight recent user/assistant messages. It returns a plain-text answer, the names of MCP tools actually executed, checked links, and a Markdown export when the selected workflow produces one. Neither provider nor tools can send messages, charge a customer or publish an offer. No chat transcript is stored by the application. Model-enabled turns send a bounded conversational excerpt and selected evidence to the model provider.

The model is fixed to `openai/gpt-4.1-mini` via Vercel AI Gateway. The official OIDC SDK gets the token from Vercel's request context; an explicit server-side `AI_GATEWAY_API_KEY` also works. `STUDIO_MODEL_DISABLED=1` disables generation. Price, contribution, target-margin and missing-input turns never request a model or reserve quota. For other questions, a model-enabled turn allows one classification and one synthesis (70 + 270 maximum output tokens, 11-second shared deadline). No model controls credentials, upstream URLs, finance assumptions, or tool arguments. The public MCP HTTP handler is invoked in-process, including on protected previews. Tool errors never count as model or tool success.

For production generation, reserve at most **100 turns/day total** and **12 turns/day per client** atomically in existing Upstash/Vercel KV using one TTL-bound EVAL that contains counters only. Configure either KV_REST_API_URL and KV_REST_API_TOKEN or UPSTASH_REDIS_REST_URL and UPSTASH_REDIS_REST_TOKEN. A missing/unreachable store fails closed to free MCP tools. These quotas cap calls/tokens, not the provider's price; use an additional Vercel AI Gateway project budget where supported. Without a Redis pair, preview and local smoke tests permit 12 turns per warm process per UTC day; this is not a distributed quota. Do not expose a paid, unprotected preview as a public deployment. Application-level throttling is 30 requests per minute per client per warm worker; the production model quota remains distributed. Only event names, categorical failure reasons and response status are reported by the gateway wrapper.

Verify a deployment by submitting a supported question and inspecting mode (`ai` or `tools`), computed values, real tool provenance, and artifact. A catalog entry, endpoint status or successful build does not verify account credit or successful inference. Preview protection and production budget are separate controls. Native external agents continue to connect at `/api/mcp`.
