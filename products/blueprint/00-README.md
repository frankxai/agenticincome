## What this is

Three complete business-plan kits — one per income model — plus the operating discipline to run whichever one you pick. This is the paid companion to the free knowledge base at [agenticincome.ai](https://agenticincome.ai): the knowledge base explains the models; the Blueprint is the desk you build one on.

Each kit is a **complete, fill-in business plan** with:

1. A full planning template (every section you must answer before you build)
2. A **worked example, start to finish** — fictional but realistic, so you can see what "done" looks like (every example is clearly labeled fictional; none of them are earnings claims)
3. **Scenario economics tables** — ranges with named assumptions, never predictions
4. A **fulfillment runbook** — which agent roles do which work, with quality gates
5. A **launch checklist** — the exact sequence from plan to first customer
6. A **kill-criterion worksheet** — the result-by-date contract that keeps you honest

## The files

| File | Model | Use when |
|---|---|---|
| `service-kit.md` | Model 1 — Services (agent-amplified labor) | You need revenue in ≤30 days and have a skill someone already pays for |
| `product-kit.md` | Model 2 — Products (packaged judgment) | You have delivered something at least twice and can package the decisions |
| `system-kit.md` | Model 3 — Systems (owned machines) | You have income already and are building assets decoupled from your calendar |

Walk them **in order** unless your situation says otherwise — the entry selector in `knowledge/02-income-models.md` (part of the free knowledge base that ships with the `/ai` pack — [agenticincome.ai/pack](https://agenticincome.ai/pack)) is the honest tiebreaker. One offer, one product, one stream. The portfolio comes later.

## How to use this with `/ai architect`

The Blueprint is designed to be **driven by the free `/ai` pack** (MIT, in this repo — you don't need to buy anything else to use it):

```
1. Install the pack (Claude Code plugin, or the portable markdown for Codex /
   Gemini CLI / Cursor / OpenCode — see packs/PORTABLE.md).
2. Run /ai assess       → produces income/00-capability-inventory.md
3. Open the kit that matches your entry model. Put it in your repo.
4. Run /ai architect and tell it:
   "Use products/blueprint/<kit>.md as the planning template.
    Fill it in from my capability inventory. Interview me for every
    section you can't derive. Flag every number as a labeled scenario."
5. The agent writes income/01-income-architecture.md — your filled kit.
6. Run /ai offer, /ai ship, /ai operate against that artifact.
```

Without the pack, the kits work as plain documents: fill them in by hand or with any capable model. Every template section is written to be answerable by a human with a text editor.

## What this is not

- **Not an income promise.** Every number in these kits is a scenario with named assumptions. Your results depend on your skills, market, execution, and luck — mostly execution.
- **Not a course.** There is no video, no community, no drip schedule. It is a working document set you fill in and act on.
- **Not consulting.** Template-level support and update notes are included; private implementation help is a separate, capped service (see /offers on the site).
